## 4. Data

### 4.1 五位"考生"：画像与版本锚点

本研究评估五份在 2026 世界杯开赛前冻结的预测产物（表 2）。三份为自研方法，两份为基准信号；任务覆盖两层——逐场层（72 场小组赛）与队伍层（48 队夺冠/出线概率）。

**P1：Elo+Poisson 统计基线**。Elo 评分驱动 Poisson 进球模型，输出 72 场小组赛的 W/D/L 概率分布。严格事前有效样本 n=71：match 1 无赛前快照（开赛后方建管线，R1 处置：排除出主汇总、单列展示）。评估版本锁定 commit `88a9bfd`（generated_at 2026-06-12T10:57:42Z）——工作区现存版本为赛后 07-19 漂移版（match 1 主胜 0.7629 → 0.7004），**禁用**，评估版从证据 bundle 提取（V-88a 预审通过：提取版与项目 72 场报告引用值逐位一致）。

**P2：Coach 对位混合预测器**（LLM-assisted hybrid）。MiniMax LLM 为 48 队 × 6 阵型选择首发 XI，随后由身价位置对位 + 20 次阵型蒙特卡洛 + Poisson 产生 W/D/L 概率。n=72，commit `1c067ec`，跨 matchday 零漂移（MD1 基线交叉核验）。注意正名：它是 LLM 辅助的混合预测器，不是端到端纯 LLM forecaster——该区分在全部比较中保持。

**P3：路径空间枚举引擎（CDS）**。将每队的夺冠路径显式枚举为路径树，汇总为 48 队夺冠与出线概率。赛前版 `cds_championship.json`（commit `ef30658`，2026-06-12；西班牙 0.0484 居首）与其归一化修正版（commit `875748b`，赛前一日内的方法论修正，修正后头号热门变更）**两版并存、同时披露**——版本选择不影响本文结论，但隐藏修正史将构成选择性报告（§5.2、§5.4）。

**P4：kimi 300-agent 群体信号（Red Source）**。10 派别 × 30 分身的 LLM 群体，经"信心加权归一化"聚合为 21 队夺冠概率（生成过程文档齐备：plan.md、42 个派别文件、聚合 JSON；聚合 metadata 生成日期 2026-06-05，导入清单日期 2026-06-10，均早于开赛）。覆盖 21/48 队——比较仅限覆盖子集，不赋默认值（PIV `baseline_coverage` 逐任务报告）。聚合层可复现性：以 300 行 inventory 按公式复算，21/21 队逐位一致（容差 0.05pp，V-kimi 预审通过）；**残余不可考项：底座模型版本**。首页展示值自 2026-06-13（commit `0ff58a7`）起逐字节冻结至今（图 S1 首页展示、图 S2 行级固化）。

**P5：市场基准（两规格）**。队伍层：Polymarket outright 隐含概率（注册基线 `baselines/market-public.json`，快照 2026-06-11T17:16Z，39 队，Yellow 级仅作描述性参照）；时间线层：77 个日度快照（2026-06-12 → 07-19）。市场只进队伍层；逐场层基线 = 均匀分布 + 永远主场 + FIFA 排名代理。前五末席之争（阿根廷 8.58% vs 巴西 8.39%，差 0.19pp）对快照日期敏感，两快照口径均披露（§4.3）。

### 4.2 证据保全与封存协议

**三级结构**。**封存仓库**（GitHub 私有仓库，投稿时转公开）→ **证据快照**（一次性只读导出：全量 git bundle + 822 文件 worktree 镜像，字节级原始，永不修改）→ **分析副本**（可写工作区，全部增补逐条记 CHANGELOG）。派生方向单向，任何分析不回写上游。

**封存的两次失败与处置（如实披露）**。其一：封存声明（2026-07-20）后，每日定时工作流继续向仓库写入 10 个 commit（2026-07-21→25，管线文件日度再生成）——属系统原设计而非人工干预，已于 2026-07-25 停用并登记；其二：原定引用锚 `e8d74aa` 经核验从未推送至 GitHub（系本地 commit 经 `pull --rebase` 改写为 `923e23a` 后推送），**本文统一引用 `923e23a`**（两者除日度生成文件外逐字节相同；原 commit 本体封存于 bundle）。已发布历史经 bundle 对账零重写（快照 origin/main 为当前 main 祖先）。

**从自律到强制**。2026-07-25 起，封存由纪律声明升级为服务端强制：main 分支启用 branch protection（禁 force-push、禁删除、强制线性历史、对管理员同效）；Actions 运行记录保留期设为 400 天（覆盖审稿周期）。协议由此可以如实声称"历史改写在托管平台侧被禁止"。

### 4.3 已知瑕疵的处置（R1–R5 + 新增漂移实例）

评估前登记并处置以下瑕疵；每条同时映射为 PIV 字段取值（§5.4）：
